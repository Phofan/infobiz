# Принципиальные решения (Практическая работа №3-4)

- **Фамилия, имя:** Серебрянников Матвей
- **Учебная группа:** ЭФБО-11-25
- **Дата выполнения:** 21.10.2026 (ПР №3) / 22.10.2026 (ПР №4)
- **Вариант:** 3 (`90 % 8 + 1 = 3`) — порог бесплатной обработки, параметр `20` (при заказе от 20 шт. обработка бесплатная).

## Решение 1. Вынос всех ограничений в константы и проверка данных до расчёта
Все граничные значения (`MIN_QUANTITY = 1`, `MAX_QUANTITY = 10_000`, `MAX_UNIT_PRICE = 5_000_000.0`, `MIN_DISCOUNT = 0.0`, `MAX_DISCOUNT = 30.0`, `VAT_RATE = 20.0`, `FREE_PROCESSING_MIN_QUANTITY = 20`) я вынес в константы класса `OrderCalculator`. Вход проверяется в методах `validate` и `isValid` сразу до любых вычислений. Если какое-то значение не подходит, программа просто выводит понятную причину ошибки и не считает заказ.

## Решение 2. Разбиение формул по отдельным методам и выбор типов данных
Чтобы не дублировать одну и ту же формулу в `main`, расчёт разбит на отдельные методы `calculateBase`, `applyDiscount`, `calculateVat`, а `calculateTotal` вызывает их по очереди. Количество хранится в `int`, потому что штуки товара всегда целые, а цена, скидка и НДС — в `double` с выводом через `%.2f` (два знака после запятой). Минус `double` для реальных денег в том, что из-за двоичного представления дробей могут накапливаться мелкие погрешности округления, поэтому в настоящих банковских программах используют `BigDecimal`.

## Результаты граничных проверок
1. **Обычное значение (`12;2490.50;5`):** `Базовая стоимость: 29886.00 руб. | Скидка: 1494.30 руб. | Сумма со скидкой: 28391.70 руб. | НДС: 5678.34 руб. | Итого: 34070.04 руб. | стандартная обработка (кол-во < 20)`
2. **Нижняя граница (`1;0.01;0`):** проходит (`Итого: 0.01 руб.`), а при `quantity = 0` выдаёт ошибку диапазона.
3. **Верхняя граница (`10000;5000000.00;30`):** проходит успешно, а при `quantity = 10001`, цене больше 5 млн или скидке `35%` выдаёт ошибку.
4. **Граница варианта 3 (`19` и `20` шт.):** при `19` шт. пишется стандартная обработка, при `20` шт. — бесплатная обработка.
5. **Отрицательная цена и кривой ввод (`5;-20;5`, `abc;100;5`):** расчёт не выполняется, выводится сообщение об ошибке.
