# Принципиальные решения (Практическая работа №5)

- **Фамилия, имя:** Серебрянников Матвей
- **Учебная группа:** ЭФБО-11-25
- **Дата выполнения:** 23.10.2026
- **Вариант:** 3 (`90 % 8 + 1 = 3`) — недельная норма, параметр `20` (`WEEKLY_NORM = 20`, переработка за неделю считается как `max(0, сумма - 20)`).

## Решение 1. Строгий разбор строки через split(";", -1) с выводом позиции ошибки
В методе `parseHours` я использовал `split(";", -1)` со вторым аргументом `-1`, чтобы пустые значения на конце строки не отбрасывались. Дальше в цикле `for` проверяется каждый из 5 элементов, и если попалось пустое место, текст вместо числа или число вне диапазона `0..16`, сразу выбрасывается `IllegalArgumentException` с номером дня `(i + 1)`, чтобы было понятно, где именно ошибка.

## Решение 2. Отдельные методы под каждый расчёт без Stream API
По условию Stream API использовать нельзя, поэтому вся обработка массива `int[]` написана на обычных циклах: сумма в `total` считается циклом `for`, дни с переработкой (`> 8` ч) в `overtimeDays` — циклом `while`, а методы `average` и `weeklyOvertime` просто вызывают уже готовый `total(hours)`, чтобы не писать цикл суммирования по несколько раз.

## Результаты граничных проверок
1. **Обычное значение (`9;8;7;10;8`):** `Сумма: 42 ч | Среднее: 8.40 ч | Дней с переработкой: 2 | Недельная переработка (норма 20 ч): 22 ч`.
2. **Нижняя граница (`0;0;0;0;0` и `4;4;4;4;4`):** `0;0;0;0;0` даёт сумму `0`, а `4;4;4;4;4` даёт ровно `20` ч (при норме 20 ч недельная переработка равна `0`).
3. **Верхняя граница (`16;16;16;16;16`):** проходит без ошибок (`Сумма: 80 ч`, `Среднее: 16.00 ч`, переработка `60 ч`).
4. **Превышение максимума (`8;8;17;8;8`):** выдаёт ошибку `Ошибка в позиции 3: значение 17 вне допустимого диапазона 0..16.`.
5. **Пустая строка, буквы и неполная строка (`""`, `8;abc;8;8;8`, `8;8;8;8`):** выдаёт контролируемые ошибки с указанием причины и позиции.
