# Принципиальные решения (Практическая работа №8)

- **Фамилия, имя:** Серебрянников Матвей
- **Учебная группа:** ЭФБО-11-25
- **Дата выполнения:** 26.10.2026
- **Вариант:** 3 (`90 % 8 + 1 = 3`) — дополнительная проверка даты, параметр `20` (`MAX_TRIP_DAYS = 20`: длительность командировки между `start` и `end` не может превышать 20 дней).

## Решение 1. Замена открытого setStatus на предметные методы переходов
В классе `BusinessTrip` полностью убран сеттер статуса. Менять состояние заявки можно только через методы `submit()`, `approve()`, `reject(String reason)`, `cancel()` и `complete(LocalDate today)`. В каждом методе сначала проверяется, можно ли сделать этот переход из текущего статуса (если нельзя — выбрасывается `IllegalStateException`), а затем проверяются входные данные (например, длина причины отказа `>= 10` символов или то, что дата завершения уже после `end`). Если проверка не прошла, объект остаётся в прежнем состоянии.

## Решение 2. Проверка дат и обязательных полей прямо в конструкторе
Все базовые проверки (`id` не пустой, даты `start` и `end` не `null`, `end` не раньше `start`, разница между датами не больше `20` дней) выполняются сразу в конструкторе `BusinessTrip`. Благодаря этому в программе вообще не может появиться объект командировки с кривыми датами. Для создания и фильтрации заявок по статусу добавлен сервисный класс `BusinessTripService`.

## Таблица переходов состояний `BusinessTrip`

| Текущий статус | Метод | Новый статус | Условие |
|----------------|-------|--------------|---------|
| `DRAFT` | `submit()` | `SUBMITTED` | Поля `id`, `start`, `end` заполнены и проверены |
| `DRAFT` | `cancel()` | `CANCELLED` | Разрешено без доп. условий |
| `SUBMITTED` | `approve()` | `APPROVED` | Только из `SUBMITTED` |
| `SUBMITTED` | `reject(reason)` | `REJECTED` | Только из `SUBMITTED`, `reason.trim().length() >= 10` |
| `SUBMITTED` | `cancel()` | `CANCELLED` | Разрешено до завершения |
| `APPROVED` | `complete(today)` | `COMPLETED` | Только из `APPROVED` и `today.isAfter(end)` |
| `APPROVED` | `cancel()` | `CANCELLED` | Разрешено пока не `COMPLETED` |
| `REJECTED`, `CANCELLED`, `COMPLETED` | любой | ошибка `IllegalStateException` | Конечные статусы, переходы запрещены |

## Результаты граничных проверок
1. **Обычный жизненный цикл (`DRAFT -> SUBMITTED -> APPROVED -> COMPLETED`):** при `today = end.plusDays(1)` успешно переходит в `COMPLETED`, а в день окончания `today = end` выдаёт `IllegalStateException`.
2. **Граница длины причины отказа (`9` и `10` символов):** причина из 9 символов выдаёт `IllegalArgumentException`, из 10 символов — переводит заявку в `REJECTED`.
3. **Граница варианта 3 по длительности (`20` и `21` день):** командировка на 20 дней создаётся нормально, на 21 день — выбрасывает `IllegalArgumentException`.
4. **Перепутанные даты (`2026-10-12` .. `2026-10-10`):** конструктор выбрасывает `IllegalArgumentException`.
5. **Попытка отменить завершённую или отклонённую заявку (`cancel()` после `COMPLETED`/`REJECTED`):** выбрасывает `IllegalStateException`.
